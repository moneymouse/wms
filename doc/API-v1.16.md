# API v1.16：移除订单锁与收据编辑约束，恢复箱子重新入库

日期：2026-10-05。

## 订单编辑

订单所有包裹出库后不再锁定，删除解锁、重新锁定和开放修订工作流。收据历史也不再阻止订单重量、客户归属、货物增删、箱子称重、分配、解绑、归档或删除。权限继续由角色决定；已出库包裹自身的重量保护仍有效，箱子重新入库后可重新称重。

`GET /api/orders/<uid>` 删除 `receipt_locked`、`receipt_lock`、`business_lock`、`financial_lock`、`lock_warnings`。订单和箱子的 `edit_policy` 不再返回 `lock_status`、`revision_open`、`financial_locked`、`has_receipt_history`；保留各动作角色权限及兼容元数据 `fully_outbound`。后者沿用有效装箱单箱子全部为 `status=1` 且有转单号的判断，不参与编辑权限计算，也不代表普通包裹或后续物流的完整履约状态。

以下接口已移除：旧 POST 请求由全局静态页面路由返回 405，旧 GET 查询返回 404。

- `POST /api/orders/<uid>/receipt-unlock`
- `POST /api/orders/<uid>/receipt-relock`
- `GET /api/admin/order-revisions/open`

历史修订表和既有版本保留，但不再读取历史开放窗口来限制编辑、报价、收款、出库或奖金分配。当前订单版本快照不再包含修订状态、原因等字段。数据库并发行锁、身份认证、角色权限、报价审核、收款审核和余额校验继续生效。

## 装箱单箱子撤销出库

沿用 `POST /api/box/<uid>/undo-ship`，JWT 请求头 `x-token`，允许 `admin` 和 `store_manager`。管理员和店长可在装箱单箱子操作栏点击“撤销出库（重新入库）”，确认后调用该接口并刷新列表；不再要求解锁，不因收据或奖金历史而禁用。

成功返回 `{"code":200,"msg":"success"}`。不存在箱子返回 404，无权角色返回 403，非出库状态返回 400，并发状态或归属变化返回 409。

回库在同一事务中恢复 `status=0`，清空 `waybill_id` 和 `date`，更新修改时间，归档当前箱成本，并记录 `box_shipment_undone` 订单版本。订单归属、装箱单归属、原单号、重量、操作员和已分配奖金保持原值；收款、成本金额及原出库记录继续保留。支持没有转单号的已出库箱及后续物流状态的箱子撤销出库。

再次确认出库时，只检查未归档的当前成本记录；创建新成本快照并追加新的出库事实。原成本继续以归档记录保留，不覆盖或重复计为当前成本。无需新增数据库字段或迁移。

## 删除与历史记录

订单被报价、成本、收款或历史修订外键引用时，删除操作改为完成归档并保留历史，不再返回财务锁冲突；有成本历史的箱子同样归档。无外键引用的记录仍可物理删除。订单归档继续级联归档关联包裹及所属财务记录，收款单和订单历史保留。

本版移除编辑控制，不重写已有收款、报价金额和奖金历史。后续财务系统改造另行实现。
