# API v1.24：出货确认单 PDF

## 导出出货确认单

`POST /api/orders/shipping-confirmation/pdf`

身份验证及角色规则与现有订单导出一致（`@verify`、`@allow()`）。这是只读打印导出，不修改订单、报价或出货状态，也不要求供应商导出的有效报价。

请求使用 JSON：

```json
{
  "uid_list": ["order-uid-1", "order-uid-2"],
  "cargo_list": ["cargo-uid-1", "cargo-uid-2"]
}
```

- `uid_list`：必填非空字符串数组，指定订单 UID，保持请求顺序并去重。所选订单不存在或已归档时，整批返回 404。
- `cargo_list`：可选字符串数组；省略、`null` 或空数组表示所选订单的全部未归档箱子。非空时只导出同时属于所选订单的未归档箱子，箱子按请求顺序排列；没有匹配箱子的订单不产生确认单。其他订单的箱子、归档箱子和不存在的箱子不会进入结果。
- 整单导出中的空订单可在含箱子的混合批次中保留抬头；整批没有可导出箱子时返回 400。

成功响应直接返回二进制 PDF：

```http
HTTP/1.1 200 OK
Content-Type: application/pdf
Content-Disposition: attachment; filename=shipping-confirmation.pdf
Cache-Control: private, no-store
```

PDF 标题仅为“出货单”。使用 A4 纵向纸张，一行并排两张订单，沿用现有蓝色抬头、灰色表头和内嵌中文字体。两列裁切边界等高，单据间保留 6 mm 间隔，中央竖虚线与行间横虚线交叉形成十字裁切线，不画外围框。普通订单保持完整；只有超过整页可打印高度的订单才拆成续单，重复客户、代理、订单编号和列标题。

订单级字段为客户名和代理名；每箱字段为唛头（`CargoTable.tag`）及原单号（`CargoTable.transfer_id`）。小号订单编号便于裁切后识别。

代理名按订单运输渠道名称精确匹配 `TransportationModeTable.name`，使用该渠道的 `channel_group`：

| 分组 | PDF 代理名 |
| --- | --- |
| 极飞 / JF | JF |
| 统仓 / TC | TC |
| YX | YX |
| 其他非空分组 | 原分组名称 |
| 分组为空或手工渠道未匹配配置 | 留空 |

已归档渠道仍保留已有订单的分组信息；不按渠道名的前缀推断代理。

错误响应为 JSON 并携带对应 HTTP 状态码：

```json
{"code": 400, "msg": "没有可导出的箱子"}
```

| HTTP 状态码 | 情况 |
| --- | --- |
| 400 | 请求不是 JSON 对象、选择数组格式错误、没有可导出箱子，或单箱字段高度超出整张确认单 |
| 401 / 403 | 身份验证或角色校验失败 |
| 404 | 所选订单不存在或已归档 |
| 500 | PDF 生成异常；返回统一错误信息 |

前端订单导出菜单新增固定选项“出货确认单（PDF）”，订单列表支持整单批量导出，订单详情支持选箱导出。仅下载成功的 PDF 响应，失败保留当前选择并显示错误信息；Excel 模板接口不可用时该选项仍可使用。
