# API v1.23 - 客户管理与订单客户联系方式权限

客户管理按客户创建人限定范围，订单详情按订单当前业务员限定联系方式访问范围。这两个条件分别校验，不以客户创建人代替订单负责人。

## 客户管理

`admin`、`store_manager` 可以查看和管理全部客户。普通 `salesperson` 可以进入客户管理页面，但只能查看、修改、删除本人创建的客户。兼有管理员或店长角色时，沿用管理角色的全部客户权限。

| 接口 | 行为 |
| --- | --- |
| `POST /api/customer` | 服务端从已认证账号记录客户创建人，不接受请求体指定或覆盖创建人 |
| `GET /api/customers_detail` | 业务员只返回本人创建的客户，含 `phone`、`wechat`；无匹配记录返回空数组 |
| `GET /api/customer_detail/<customer_id>` | 业务员只能读取本人创建的客户详情，超出范围返回 HTTP `403` |
| `PUT /api/customer/<customer_id>` | 业务员只能修改本人创建的客户，创建人不可修改 |
| `POST /api/del_customer/<customer_id>` | 业务员只能删除本人创建的客户，沿用既有订单关联保护 |

普通 `GET /api/customer_list` 继续提供客户编号与名称，供创建订单、选择客户使用，不返回客户手机号或微信。

## 订单详情联系方式

新增 `GET /api/orders/<uid>/customer-contact`，使用现有 `x-token` 认证。

- `admin`、`store_manager` 可查看任意订单关联客户的手机号和微信。
- 普通 `salesperson` 仅可查看当前 `salesman_id` 为本人的订单；其他业务员的订单或未分配业务员的订单返回 HTTP `403`。
- 校验以当前订单归属为准，调整业务员后原业务员失去该订单的联系方式访问权限。
- 业务员查看本人订单时，不要求客户由本人创建。
- 客户由服务端从订单关联关系中取得，请求不能指定其他客户编号扩大访问范围。
- 前端仅在有权限时展示「客户手机号」「客户微信」，并调用此订单接口；无权限时隐藏两项。

成功响应沿用 `{code:200,data:...}` 结构，`data` 包含首个关联客户的 `id`、`name`、`phone`、`wechat`，空联系方式为空字符串。订单没有关联客户时 `data=null`。访问会记录敏感信息审计日志，响应禁止缓存。订单不存在或已归档时返回 HTTP `404`，未登录时返回 HTTP `401`，无相应角色时返回 HTTP `403`。

## 历史客户与数据库迁移

客户表新增可空的 `created_by_id` 创建人字段及查询索引。新建客户自动保存当前账号；已有客户不根据订单负责人推测创建人，创建人为空时不出现在业务员的客户管理范围中，管理员和店长仍可管理这些客户。业务员本人订单的联系方式仍通过订单接口按当前归属读取。

数据库迁移为 `46b1c2d3e4f5`，前序为 `35a0b1c2d3e4`。发布时应先执行 `alembic upgrade head`，再启用对应后端和前端；现有部署需显式执行迁移，或在启动前设置 `RUN_MIGRATIONS=true`。
