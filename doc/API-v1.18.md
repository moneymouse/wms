# API v1.18：订单详情收款与收款管理默认本人筛选

日期：2026-10-05。

订单详情在存在有效报价且登录人有创建收款权限时显示“收款”。使用订单 UID 精确读取最新可收余额，沿用收款管理的登记弹窗、`POST /api/receipts` 和 `GET /api/receipts/<id>/pdf` 创建收款单和生成收据。普通业务员只可登记当前有效报价人为本人的订单，管理员可以代登记；有效报价不代表仍有可收余额，已结清或被待审核金额占满的订单不会返回可收款记录。

## 查询参数

| 接口 | 新增参数 | 行为 |
| --- | --- | --- |
| `GET /api/receivables/orders` | `order_uid` | 精确匹配订单 UID，与客户、日期、负责人及可收余额规则同时生效，在分页前筛选。 |
| `GET /api/receipts` | `owner_id` | 管理员及财务按收款单创建人 `creator_id` 筛选。 |
| `GET /api/receivable-adjustments` | `owner_id` | 管理员及财务按订单当前有效报价人 `quoter_id` 筛选。 |
| `GET /api/receivable-adjustments` | `order_uid` | 精确匹配订单 UID，与差价状态及权限范围同时生效，在分页前筛选。 |

`order_uid` 会去除两端空白，空值等同未传；仅匹配完整 UID，不作为模糊关键词。没有匹配记录或订单不在当前业务员范围内时，列表返回 `data=[]`、`total=0`。

管理员及财务不传 `owner_id` 时仍可查询全部允许查看的记录。业务员传入任意 `owner_id` 均不会扩大权限：可收款订单及差价列表始终限制为本人当前有效报价，收款单始终限制为本人创建。单笔差价详情原有的 `403` 权限校验继续适用。

管理员进入收款管理页面时默认选中本人，可切换为其他业务员或全部。可收款订单和差价按报价负责人筛选，收款记录按创建人筛选；管理员代登记的收款记录归创建该单的管理员。

订单详情和收款管理共用剩余应收计算：`应收 − 已审核实收 − 已生效结清差额 − 本次收款`，其他待审核收款不参与默认结清判断；合计小于 30 元默认已结清，仍可手动修改。

收款创建、审核、差价补收、结清差额与 PDF 响应结构不变，无新增数据库字段或迁移。
