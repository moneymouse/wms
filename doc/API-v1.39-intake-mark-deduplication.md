# API v1.39：纸质装箱单唛头自动去重

纸质装箱单上传识别、核对确认与手动创建共用 `PackingListModel._generate_unique_list_number`。

## 唛头规则

- 去除首尾空格并转大写。没有重名时直接使用规范化唛头。
- 重名时追加后端当前日期，例如 `MARK-20261007`；同日仍重名则依次使用 `MARK-20261007-2`、`MARK-20261007-3`。
- 已归档装箱单仍占用唛头，因为数据库唯一约束覆盖所有记录。
- 自动追加尾数时保留完整日期及序号，必要时缩短原唛头前缀，使最终唛头不超过 `list_number` 的 64 字符限制。

## 识别结果

`POST /api/intakes` 自动启动识别，或调用 `POST /api/intakes/{uid}/recognize` 重试识别。成功后的读取结果中，`recognition_result.mark` 已按上述规则生成可用唛头。

若因重名改名，结果新增可选字段 `recognition_result.original_mark`，保存规范化后的原唛头，并在 `warnings` 中说明自动替换。核对页面显示替换后的唛头及原唛头说明。

```json
{
  "recognition_result": {
    "mark": "MARK-20261007",
    "original_mark": "MARK",
    "warnings": ["唛头MARK已存在，已自动改为MARK-20261007"]
  }
}
```

识别结果是预览；正式装箱单仍在上传人核对并确认后创建。人工已经保存的草稿继续优先于识别候选。

## 确认结果

`POST /api/intakes/{uid}/confirm` 保持原请求结构：

```json
{"version": 3, "reviewed": true}
```

确认时再次分配唯一唛头，原先因唛头重名返回的 `409` 改为自动添加日期尾数并完成上传。若识别预览的唛头在核对期间又被占用，且用户仍使用该预览唛头，系统从 `original_mark` 分配下一个可用序号，避免重复追加日期。用户修改唛头后按用户修改的唛头分配。

最终返回的 `draft.mark`、`display_name`、正式装箱单 `list_number` 和每箱 `tag` 一致。仅草稿唛头写回最终值，保留原草稿的其他历史字段。照片展示文件名随最终唛头更新。

数据库唯一约束检测到并发占号时会重新分配，最多尝试三次。箱子、操作工人和装箱单在同一事务内创建；版本冲突、箱号重复、未核对或其它原有校验仍按原规则返回错误。

无需数据库迁移。
