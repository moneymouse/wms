# API v1.44：删除本人未完成的纸质单上传

创建装箱单的「拍照上传纸质单」中，「我的未完成上传」新增删除入口。此入口删除尚未核对完成的纸单来源及其私有原图，不能删除正式装箱单。

## 权限与状态

`DELETE /api/intakes/<uid>` 使用现有 `x-token` 认证。沿用纸单上传角色权限，且只有上传者本人可以删除，管理员、店长或其他职员也不能经此入口删除他人的上传。

请求体为 JSON：

```json
{"version": 2}
```

只接受正整数版本，首次删除须与当前来源版本一致。来源必须为现有 `pending` 状态，并且 `packing_list_uid`、`confirmed_by`、`confirmed_at` 均为空。已核对的 `confirmed` 来源、已关联正式装箱单的来源和正式装箱单删除留下的 `deleted` 历史来源均返回 409。错误角色返回 403，未认证返回 401，非法 JSON 返回 400。

删除事务先将来源置为新增的内部 `deleting` 状态，撤销识别任务标识及结果，同时移除图片元数据并写入现有持久清理队列。事务提交成功后才删除文件；全部清理完成后物理删除来源记录。此过渡状态不允许读取详情、图片、保存草稿、识别或确认，相关来源路由返回 404。它与原有正式装箱单删除的 `deleted` 历史来源不同。

## 列表及恢复

`GET /api/intakes/my-packing-lists?status=uploading` 中本人的未完成条目新增：

```json
{"version": 2, "can_delete": true, "photo_cleanup_pending": false}
```

列表状态 `uploading` 是 `pending` 来源的展示状态。删除尚未完成的 `deleting` 来源仍保留在本人列表，返回 `photo_cleanup_pending: true`；前端改为显示「重试删除」，不能继续检查上传。正式单据条目不返回这些删除能力字段。

成功响应：

```json
{"code": 200, "data": {"deleted": true, "photo_cleanup_pending": false}}
```

来源成功删除后，使用合法版本重复请求同一地址返回相同成功结果。`deleting` 来源重试允许使用首次确认时的旧版本，只完成同一来源的清理，不重新执行核对或创建单据。

如果文件清理或清理完成后的数据库提交失败，保留队列及来源过渡记录，返回：

```json
{
  "code": 503,
  "msg": "纸单已停止上传，删除清理尚未完成；请重试删除",
  "data": {"deleted": true, "photo_cleanup_pending": true}
}
```

首次数据库提交失败时不清理文件，来源及图片元数据回滚；若提交已成功但确认响应丢失，核对持久状态后返回上述可重试信息。版本或状态冲突返回 409，前端刷新列表后要求重新确认，不自动用新版本删除。

## 图片安全及并发

只允许与来源 ID、照片 ID 和 MIME 类型完全一致的 `<intake_uid>/<photo_uid>.<扩展名>` 私有路径。清理复用 `paper_photo_storage` 的目录穿越、符号链接及普通文件检查，并在删除前检查任何仍有效的图片引用；不会调用旧的静态装箱单图片删除逻辑。不存在的文件视为已清理。

行锁与来源版本比较防止删除、保存、确认和识别互相覆盖。若确认先提交，删除被拒绝；若删除先提交，确认事务回滚正式装箱单及库存写入。已经发往识别提供方的请求可能继续计算，但过渡状态和失效的任务标识会阻止结果写回。

无需新增数据库结构；使用当前工程已有的纸单私有文件存储及 `paper_photo_cleanup` 表。本次开发不执行生产迁移、删除、重启或部署。
