# API v1.17：箱子出库后固定箱号和原单号

日期：2026-10-05。

装箱单箱子一旦出库，箱号 `box_number` 和原单号 `transfer_id` 不可修改，包括管理员。撤销出库后这两个标识仍然固定；转单号 `waybill_id` 继续按原有角色权限编辑，回库后重量继续可调整。普通包裹不受新增的箱子标识保护规则影响。

## 修改接口

`PUT /api/box/<uid>` 和 `PUT /api/cargo/<uid>` 均执行相同校验，直接模型调用也适用。当前为出库或后续状态、存在出库时间、存在出库记录，或有任意箱成本历史（含归档记录）的箱子，其箱号与原单号均固定。

请求实际改变任一标识时返回 HTTP 409：

```json
{"code":409,"msg":"箱子已出库，箱号和原单号不可修改"}
```

校验在任何资料修改前完成。同一请求中的备注、品名、操作员、重量、转单号等内容也不写入，不生成订单版本。重复提交相同箱号或原单号允许成功；箱号整数和等值字符串按同值处理，原单号比较忽略两端空白，同值不会产生版本。

首次出库前仍可修改箱号和原单号；兼容录号出库请求可在首次确认的同一事务中提交最终标识。出库后即生效，不需要订单锁定或解锁，也不取决于收据历史。

## 读取接口及前端

装箱单嵌套箱子、单箱详情、未分配/订单箱子列表和订单货物列表中的箱子新增 `identity_editable` 布尔字段。`false` 表示标识固定，前端将箱号与原单号设为只读并在保存时省略这两个字段。当前出库/后续状态仍作只读兜底，兼容旧响应。

装箱单操作区固定两行，每行两个按钮：

- 第一行：编辑、撤销出库。
- 第二行：归档（垃圾桶图标）、删除（无图标）。

权限隐藏某按钮时保留操作分行。撤销出库沿用 `POST /api/box/<uid>/undo-ship` 和管理员、店长权限，按钮文字缩短为“撤销出库”。

使用现有状态、时间、出库记录和成本历史判断，无新增数据库字段或迁移。订单锁及收据历史编辑限制继续维持 v1.16 的移除结果。
