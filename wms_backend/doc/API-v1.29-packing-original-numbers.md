# API v1.29：装箱单批量生成原单号

装箱单详情页支持选择箱子后点击「生成原单号」。未分配订单的箱子同样可以生成；已有原单号时，前端先显示替换确认，确认后立即随机生成并保存。没有选择的箱子保持原单号，打开页面或选择箱子不会自动生成号码。

## 原单号格式

v1.32 起所有自动生成的原单号和订单号统一使用 `D` 前缀与 `L` 后缀，中间保留原来的 9 位数字、首位 `8`，例如 `D800012345L`，共 11 个字符。此规则覆盖装箱单批量生成及订单详情两个生成接口，详见 [API v1.32](API-v1.32-shipping-layout-and-number-format.md)。现有已保存号码和手动输入格式不作修改。

安全随机生成、保留前导零、对订单号及原单号完整字符串查重（包含归档记录）、最多重试 100 次、MySQL/MariaDB 专用连接生成锁、SQLite `BEGIN IMMEDIATE` 等规则沿用 v1.25。无需新增数据库字段或迁移。

## 批量生成接口

`POST /api/packing-lists/<packing_uid>/boxes/generate-original-numbers`

要求 `x-token`，允许 `admin`、`store_manager`、`salesperson`、`clerk`（含多角色账号）。

```json
{
  "box_uids": ["BOX_A", "BOX_B"],
  "expected_values": {"BOX_A": null, "BOX_B": "原有号码"}
}
```

`box_uids` 是不重复、非空的箱子 UID 数组。可省略 `expected_values`；传入时必须包括全部所选箱子的页面已保存原单号，每个值为字符串或 `null`。前端始终携带该字段以拒绝并发覆盖。不接受指定号码或其它字段。

成功响应按请求箱子顺序返回：

```json
{
  "code": 200,
  "msg": "原单号已生成",
  "data": {
    "packing_list_uid": "PACKING_UID",
    "generated_count": 2,
    "boxes": [
      {"uid": "BOX_A", "order_uid": null, "transfer_id": "D800012345L"},
      {"uid": "BOX_B", "order_uid": "ORDER_UID", "transfer_id": "D800012346L", "current_version": 3}
    ]
  }
}
```

同一批次在一个事务中执行。先锁定相关订单、箱子和装箱单并核对全部箱子，任何一个箱子失效、已出库、归属变化、原单号被修改或生成失败，整个批次都回滚。仅修改所选箱子的 `transfer_id` 与 `update_date`，不分配订单、不触发出库或追踪注册、不修改转单号与其它业务字段。

已分配订单的箱子按订单记录一次 `original_number_generated` 版本，包含该批次该订单所有箱子的号码变更；未分配订单的箱子无需订单版本。接口由操作日志记录批量动作。

当前已出库或存在当前出库日期的箱子不能生成；撤销出库并重新入库后沿用 v1.26 的可编辑规则，历史记录保留。归档箱子、归档装箱单、归档订单不可生成。

| HTTP / code | 含义 |
| --- | --- |
| 400 | 请求格式或所选 UID / 并发值格式无效 |
| 401 / 403 | 缺少有效登录或角色不允许 |
| 404 | 装箱单、箱子或关联订单不存在 / 已归档 |
| 409 | 箱子不属于当前装箱单、订单归属变化、已出库或原单号已变化 |
| 503 | 生成锁繁忙或查重重试耗尽 |
