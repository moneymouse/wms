# 装箱单一票多件原单号

`POST /api/packing-lists/{uid}/boxes/generate-original-numbers` 新增可选布尔值 `multi_piece`，默认 `false`。`box_uids`、`expected_values` 和原有权限保持不变。

```json
{
  "box_uids": ["box-1", "box-2"],
  "expected_values": {"box-1": "D800000042L-1", "box-2": null},
  "multi_piece": true
}
```

- 未勾选「一票多件」：仅支持为空号箱子独立随机编号，所选箱子包含已有号码时禁止生成，接口返回 409。已有原单号始终保留，不提供替换。
- 勾选且所选箱子均为空号：生成未占用的 `D8xxxxxxxxL` 主单号，按箱号顺序生成 `主单号-1`、`主单号-2` 等。
- 所选箱子含同一主单号的已有编号：保留这些编号，仅给空号箱子追加；从系统内已有最大后缀继续，包含未选箱子、归档记录及订单号占用。全选箱子已有同票编号时不修改数据、不新增订单修改版本，`generated_count` 为 0。
- 混入普通原单号或不同主单号时返回 409，不覆盖、不部分保存。现有已出库限制、箱子所属装箱单检查、原单号并发校验仍然生效。

本功能只接受当前装箱单内的箱子，不要求先分配订单，不创建分组表或新字段。号码分配沿用现有数据库生成锁，避免并发追加重号；新随机号码不会复用已有一票多件的主单号。

响应仍包含全部所选 `boxes` 的最终原单号；`generated_count` 表示本次实际新编号的箱数，已有同票编号不计入。

收付款详情中的「参考订单」「备注装箱单箱子」「箱子当前所属订单」同时支持点击跳转到对应详情，使用已有 UID，不新增接口。缺少 UID 的历史快照保留文字显示。
