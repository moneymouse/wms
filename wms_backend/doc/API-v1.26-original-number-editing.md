# API v1.26：撤销出库后恢复原单号编辑

日期：2026-10-06。

箱子撤销出库后（`status=0`、`date=null`）恢复原单号 `transfer_id` 的手动修改和随机生成。原出库事实、归档成本和订单版本历史保留。再次出库后，新的原单号继续受到当前出库状态保护。箱号 `box_number` 沿用历史保护规则，撤销出库后仍不可修改；普通包裹的原单号编辑规则保持不变。

本版本替代 v1.17、v1.21 和 v1.25 中“撤销出库后箱子原单号仍固定”的规则，无需数据库迁移。

## 修改与生成接口

`PUT /api/box/<uid>`、`PUT /api/cargo/<uid>` 以及直接模型更新采用相同校验。箱子当前为出库或后续状态，或仍存在当前出库时间时，实际修改原单号返回 HTTP 409：

```json
{"code":409,"msg":"箱子当前已出库，原单号不可修改；请先撤销出库"}
```

`POST /api/orders/<order_uid>/cargo/<cargo_uid>/generate-original-number` 同样使用当前出库状态校验。历史出库记录与归档成本不再阻止生成原单号；号码查重、角色权限、归档保护、并发检查和历史记录沿用 v1.25。

实际修改已经出库过的箱号仍返回 HTTP 409：

```json
{"code":409,"msg":"箱子已有出库历史，箱号不可修改"}
```

上述拒绝均在任何字段保存前完成，整次请求不写入资料或版本。同值提交仍可成功。

## 读取接口与前端

货物详情与列表、箱子详情与列表、装箱单嵌套箱子新增 `original_number_editable: boolean`。箱子在当前未出库时为 `true`，当前已出库或仍有出库时间时为 `false`；普通包裹为 `true`。该字段只描述出库状态限制，角色权限和归档限制仍须分别满足。

现有 `identity_editable` 字段继续描述箱号历史保护；前端分别使用两个字段控制箱号和原单号。不要再用 `identity_editable` 同时锁定原单号。

订单详情页仅在编辑状态允许点击订单号与原单号的随机生成按钮；查看状态下禁止点击。生成仍需用户显式点击，按 v1.25 在请求成功时立即保存对应号码。
