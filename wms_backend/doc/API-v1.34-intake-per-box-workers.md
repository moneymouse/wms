# API v1.34：纸单识别逐箱操作人员

日期：2026-10-06。扩展 [上传者检查流程 v1.30](API-v1.30-uploader-check-and-shipping-drafts-page.md)，保持现有接口路径、角色、本人操作范围、乐观版本校验和显式 `reviewed:true` 确认要求。

## 草稿保存与确认

`PUT /api/intakes/<uid>/draft` 的 `draft.boxes[]` 新增 `worker_ids`，每个箱子独立选择实际操作人员。ID 必须为正整数，去重后每箱最多 4 人，且均为已批准的 `worker` 或 `employee` 账号。每张纸的不同箱子可选择不同人员，不限制整张纸的人员合计数量。

```json
{
  "version": 3,
  "draft": {
    "mark": "ABC",
    "operator_name": "纸面署名",
    "boxes": [
      {"box_number": 1, "item_name": "衣服", "count": 12, "weight": 8.5, "worker_ids": [1]},
      {"box_number": 2, "item_name": "鞋子", "count": 6, "weight": 5.2, "worker_ids": [3, 4]}
    ]
  }
}
```

规范化保存结果仅返回逐箱 `worker_ids`，不再返回顶层权威 `draft.worker_ids`。`operator_name` 仍为纸面署名展示信息，不代替真实账号选择。品名、件数、重量与人员不完整时可以保存草稿；缺失人员规范化为 `[]`。无效或未批准的人员 ID 不允许保存，错误包含对应行号，失败不修改已存草稿或版本。

`POST /api/intakes/<uid>/confirm` 要求每箱至少选择一名真实操作人员，并重新验证账号当前批准状态及工人角色。所有箱子先完成验证，再同事务创建装箱单、箱子和逐箱 `BoxWorker` 关系；某一箱失败时整张纸不创建任何库存记录。确认不把一个全局列表绑定到全部箱子。

兼容已有草稿：顶层旧 `draft.worker_ids` 仅作为**缺少** `boxes[].worker_ids` 字段的行的后备值；显式 `worker_ids:[]` 保持为空并阻止确认，不能回退到旧全局列表。所有箱子均有显式选择时不使用旧全局列表。读取既有及已确认来源不会改写历史原始 JSON；旧草稿确认时也保留其历史证据。

## 识别候选

识别提供商抄录箱子上明确标注的人员到对应 `boxes[].operator_name`；没有逐箱标注时省略该字段。服务按每行姓名分别匹配已批准工人，全部姓名都唯一匹配才形成该箱 `worker_ids`。同名、未匹配、部分多人匹配或超过每箱 4 人时返回空选择和对应箱子的警告，等待本人核对。

候选中已有的逐箱 `worker_ids` 优先并单独验证；显式空列表不被姓名或全纸署名覆盖。只有同时缺少逐箱人员 ID 和逐箱署名时，完整纸面的唯一可绑定署名才可作为候选后备值；显式逐箱空署名也不继承。旧候选顶层 `worker_ids` 保留为兼容提示，逐箱列表为选择依据。识别只保存独立候选，不覆盖已编辑草稿，也不直接创建箱子或工人关系。

已删除来源返回 404，不能再次保存、确认或启动识别。后台识别任务在调用前及持久化前确认来源仍为待核对且任务身份一致，防止删除后迟到结果重新保存候选。

本扩展复用现有草稿 JSON 和逐箱工人关系，无新增数据库迁移。
