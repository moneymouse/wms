# API v1.41：财务退回修改通知

财务在待确认客户收付款详情中选择“退回修改”后，系统自动向该收据的原登记员工发送站内消息。通知通过 [站内消息服务](API-v1.40-in-app-messages.md) 投递，员工可在右下角收件箱查看退回原因，并直接进入对应收据详情修改、重新提交。

## 退回接口

沿用 `POST /api/finance/v2/payments/<payment_id>/return`，请求及返回结构不变：

```json
{
  "version": 2,
  "reason": "金额与银行回单不一致，请核对并修改。",
  "idempotency_key": "payment-return-123-v2"
}
```

原有财务权限、登记人不能审核自己的记录、待确认状态和版本检查继续生效。退回原因必填。退回成功后，收据回到 `draft`，保存审核人及退回原因，同时创建消息。

## 收件人及消息内容

收件人取 `FinancePayment.created_by_id`，即原登记员工。是否由其他员工代提交、备注了哪些订单或箱子均不改变收件人。

自动通知适用于非期初的客户收付款。登记员工仍存在且已审批通过时接收消息；历史记录未记录登记人、登记员工已删除或未审批通过时，跳过消息并记录警告，退回操作仍可完成。

消息分类为 `finance_return`，业务类型为 `finance_payment`，业务编号为收据 ID。标题与正文提供单号、退回原因及修改后重新提交的提示，来源显示财务审核人，处理路径为：

```text
/receipts?payment_id=123
```

消息与收据状态、审计记录在同一个数据库事务中提交。投递失败时整笔操作回滚，避免收据已退回而消息丢失。同一幂等请求重试返回原结果；消息事件编号使用 `finance:payment:return:<payment_id>:<退回后的版本>`，重新提交后再次退回会生成一条新消息。

## 收据详情跳转

`/receipts?payment_id=<正整数 ID>` 自动打开收付款记录标签及对应详情。详情直接读取已有的 `GET /api/finance/v2/payments/<payment_id>`，不依赖当前列表筛选或分页。查询继续由后端执行原有权限检查，业务员只能访问自己登记的客户收付款。

关闭详情时移除 `payment_id` 参数，保留其他查询参数。再次从通知进入会重新读取当前状态：记录仍为草稿时，可使用“编辑草稿”修改，再“提交”财务确认；已经重新提交或生效时，按现有状态提供操作。

消息已读仅表示员工已查看通知，不改变收据的业务状态。重新提交后，旧通知保留在收件箱中供查阅。

本次不新增数据库结构。部署环境需已应用站内消息表迁移 `9bf6c7d8e9f0`。
