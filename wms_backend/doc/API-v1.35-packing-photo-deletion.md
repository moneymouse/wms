# API v1.35：删除装箱单及关联照片

`DELETE /api/packing-list/<uid>` 继续要求 `x-token`，仅管理员和店长可使用。装箱单含上传照片或纸质回传来源不再单独阻止删除；成功响应仍为 `{ "code": 200, "msg": "success" }`。

## 数据与历史

- 已出库箱子或仍有当前出库日期的箱子继续阻止删除，返回 409；必须先撤销出库。删除失败时装箱单、纸单照片和上传文件保持原样。
- 无成本历史时沿用原行为，删除装箱单并解除箱子的装箱单关联；订单、包裹、工人绑定等原有记录不会因照片清理而额外删除。
- 存在成本历史时保留已归档的装箱单和箱子，成本、出库、财务和订单历史引用继续有效；相应照片仍会清理。
- 纸单来源保留上传人、核对人、草稿及时间等元数据，标为 `status: "deleted"`，解除 `packing_list_uid` 并删除其 `paper_intake_photos` 二进制行，撤销识别任务标识。来源详情、照片、草稿修改、再次确认及再次识别均返回 404，不会通过旧请求重新生成库存，也不会再出现在“我的装箱单”中。
- 单独调用归档接口仍保留照片和来源；清理照片仅属于删除操作。

## 本地上传照片

数据库删除事务提交成功后才清理文件；首次提交失败会回滚来源及箱子修改，并保留全部文件。只处理 `/static/uploads/photos/` 下的直接子文件，支持与上传一致的 `png`、`jpg`、`jpeg`、`gif`、`webp` 扩展名。路径按 URL 的本地路径解析，查询参数和片段不改变照片归属。

其他装箱单（包括归档记录）仍引用的照片文件保留。外部地址、目录穿越、子目录和非照片文件不作为清理目标；不沿符号链接删除文件或访问上传目录之外的位置。不存在的文件视为已经清理。

## 清理失败与重试

数据库删除提交后，如文件权限、符号链接保护或清理完成后的元数据提交出错，返回 JSON 500：

```json
{
  "code": 500,
  "msg": "装箱单已删除，部分照片清理尚未完成；请重试删除以完成清理",
  "data": {"deleted": true, "photo_cleanup_pending": true}
}
```

装箱单保留为列表不可见的归档记录，内部 `deleting:<原状态>` 标识及照片引用保留，继续向同一个 `DELETE` 地址请求即可完成清理。已经移除的文件无需恢复，也不会重复写入订单变更历史。清理成功后无成本历史的记录完成硬删除；有成本历史的记录保留归档并清空照片引用。

待清理记录不能通过保存照片、完成装箱单或添加箱子覆盖。`deleting:` 状态为内部保留值，创建、更新和完成接口拒绝外部传入此类状态，避免绕过正常删除校验。

原有 401/403 角色保护及 404 未找到响应保持不变；已经完成硬删除后再次发起普通 `DELETE` 返回 404。无需数据库迁移。
