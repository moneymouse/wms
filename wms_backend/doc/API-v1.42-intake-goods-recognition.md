# API v1.42：纸单常用品名识别与一箱多品名

日期：2026-10-08。

## 品名识别参考

每次纸单识别或重试都会读取当前 `goods_names` 中文、英文品名，中文优先，最多 400 项；识别请求对参考列表去重并限制总字符数为 12000。另附常见服装、鞋包、首饰和日用品，品名库为空时仍可参考常见商品。

DeepSeek 在字迹潦草、形近字、错别字或同音字有歧义时优先参考合理的商品品名。清晰的列表外商品仍按纸面保留；无法辨认的内容留空，修正或疑似判断须在 `warnings` 提醒人工核对。参考列表属于资料，不允许执行其中的指令。

## 每箱商品明细

识别候选、`PUT /api/intakes/<uid>/draft` 和读取详情的 `draft.boxes[]` 支持 `item_details`，沿用手动录入的商品结构：

```json
{
  "box_number": 1,
  "item_name": "衣服、裤子",
  "count": 12,
  "weight": 8.5,
  "worker_ids": [2],
  "item_details": [
    {"item_name": "衣服", "piece_count": 8, "customs_code": ""},
    {"item_name": "裤子", "piece_count": 4, "customs_code": ""}
  ]
}
```

一个箱子仍只有一个箱号、重量和操作人员选择，最多填写 100 项商品。所有明细件数明确且为正整数时，箱级 `item_name` 是用顿号连接的品名摘要，`count` 为明细件数之和。每项件数及总件数均不能超过 2147483647，品名摘要最多 256 字。识别所得整数件数归一化为整数，避免供应商返回的数值字符串影响确认。

多品名只有纸单总件数时，明细 `piece_count` 为 `null`，保留原 `count` 供核对，不能按总数分配或推算每种商品件数。部分明细未填写时仍可保存和恢复草稿，但 `POST /api/intakes/<uid>/confirm` 要求每项品名和正整数件数完整；确认后实际商品明细保存在箱子的 `item_details`，不再合并成一个商品。识别不会推测海关编码；已保存明细中的 `customs_code` 保留，最多 64 字。

旧单品名 `item_name/count` 请求继续兼容。旧多品名文本按顿号、中英文逗号、分号或换行拆为独立明细，原总件数作为参考，各项件数需补全。显式空 `item_details: []` 可保存为未完成草稿，确认时拒绝。连续箱“同上”仅沿用品名，不复制上一箱明细件数，也不跨缺号、未知品名或不同唛头继承。

## 前端核对

检查页每箱的品名输入框显示 `衣服 x 8、裤子 x 4` 格式的摘要。点击输入框展开下拉面板，在面板中添加、删除商品，逐项修改品名和件数；品名自动完成使用现有中文品名库及手动录入常用品名。修改会实时更新摘要，点击“完成”、点击面板外部或按 Escape 收起面板。总件数自动汇总；有未知件数时显示纸单合计及“明细待补全”，确认按钮保持禁用。批量修改品名可指定商品行，只修改该行并保留其余商品和件数。
