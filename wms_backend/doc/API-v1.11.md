# API v1.11：工人绑定与装箱单审核入口

日期：2026-10-02。延续 [API v1.10](API-v1.10.md) 的照片上传与自动识别，调整工人视图、审核界面和操作人员的业务关联。

## 工人身份与确认

草稿和识别候选新增 `worker_ids: number[]`，保存实际员工账户 ID，最多 4 位；`operator_name` 仅保留纸面文字作为来源参考。`GET /api/intakes/workers` 仅审核人员可调用，返回 `{code:200,data:[{id,name}]}`，仅列出已批准且拥有 `worker` 或兼容 `employee` 角色的账户，不暴露手机号或凭据。

识别完成后，服务以纸面姓名对批准工人做精确唯一匹配。未找到、同名或多人仅部分匹配时，不自动绑定，加入核对疑点，由核对人员在表单中选择真实工人。识别文字不会创建员工账户，也不自动把回传人当成作业人员。

`PUT /api/intakes/:uid/draft` 可暂存空 `worker_ids`；绑定对象必须为有效批准工人。`POST /api/intakes/:uid/confirm` 至少需要 1 位有效工人，并在确认事务内为每箱写入既有 `BoxWorkerTable` 关系。人员在确认前被拒绝或移除工人角色时，确认失败且不写库存。

正式装箱单的 `creator_id` 使用原始回传人 `submitted_by`，审核人员仍写入回传记录的 `confirmed_by`。既有正式装箱单不批量改写；旧纸单草稿未绑定工人时，需要核对后选择。

序列化新增 `draft_is_manual`，用于区分初始空草稿和已保存人工内容。核对页首次加载或识别完成时，直接把候选呈现为可编辑表单；有人工作业内容或未保存修改时不覆盖。采用候选不立即写库存，主动作“确认生成装箱单”在有修改时先保存最新草稿，再确认。

## 本人装箱单清单

`GET /api/intakes/my-packing-lists?page=1&page_size=20&mark=ABC` 返回本人创建的手动装箱单、本人待核对纸单、本人已确认拍照装箱单。已确认纸单与正式单合并为一条；所有角色调用该接口均限定本人。最长 64 字唛头包含查询，分页尺寸最多 100。

```json
{
  "code": 200,
  "data": {
    "items": [{
      "uid": "record-uid",
      "mark": "ABC-001",
      "source": "paper",
      "status": "pending_review",
      "created_at": "2026-10-02T09:30:00",
      "box_count": 2,
      "packing_list_uid": null
    }],
    "total": 1, "page": 1, "page_size": 20
  }
}
```

`source` 为 `manual` 或 `paper`；`status` 为 `pending_review`、`draft` 或 `completed`。正式记录提供 `packing_list_uid`，待核对纸单仅提供状态，不提供识别候选、疑点或图片详情。列表读取不加载原图字节。

纯工人/兼容员工访问既有 `GET /api/packing-lists` 也强制限定 `creator_id`，访问他人的装箱单详情和装箱单 PDF 会被拒绝。管理、文员、业务和财务角色保持原业务可见范围。

## 页面流程

- “创建装箱单”提供“手动录入”和“拍照上传纸质单”两个入口，照片即可提交。工人通过“我的装箱单”查看本人两种来源的记录，待核对纸单不提供解析详情入口。
- 文员在“装箱单列表”标题同行最右侧点击蓝色 link 按钮“待核对纸质单?”，进入审核列表。独立侧栏“纸单回传”入口移除，工人不进入审核路由。
- 核对页直接展示一张可编辑的装箱表与工人绑定选择，不再单独展示识别候选表或要求点击填入。疑点集中在定高滚动区域；确认是主按钮，保存草稿为次要操作。
- 创建页本地未提交标签草稿按登录用户分隔，避免同浏览器切换工人后混用草稿缓存。原有未分隔缓存保留，不自动跨用户导入。

员工绑定逻辑读取系统当前配置数据库的用户模型；流程已接入正式主应用。当前部署方式和模板接口见 [API v1.12](API-v1.12.md)。

## 验证

后端隔离测试 62 项及未改变的识别适配 65 项通过。真实创建端点验证兼容 `employee` 角色可手动创建，创建人取登录身份，不接受客户端伪填创建人；匿名和财务创建权限仍受限制。

前端验证覆盖工人个人清单、创建入口与文员审核入口、自动填表且不覆盖人工内容、疑点定高滚动、工人绑定以及确认时先保存草稿。前端构建通过，已有其他页面 lint 提示保持不变。

工人手机和窄屏使用卡片清单，桌面使用表格；已验证 390px 手机与 1280px 桌面布局，疑点区域实际高度为 132px、纵向内部滚动，手机页面宽度保持 390px。前端针对性用例共 47 项通过（核对 27、个人清单 9、入口 3、既有应用导航 8）。

在隔离预览中从工人的创建页上传合成纸单 `VERIFY-UI-1002`，识别候选自动进入编辑表，并匹配批准示例工人 ID 2。核对人员直接点击确认后，四箱均持久化绑定 ID 2，正式装箱单创建人仍为原工人，审核人为独立核对账号；没有要求手动点击填入候选或先单独保存。
