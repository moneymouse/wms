# 统一订单应收与财务核销

本次与 [客户收付款 v1.22](API-v1.22-customer-payments.md)、[包裹移除 v1.21](API-v1.21-outbound-removal.md) 配套。

## 操作分工

- 业务员在统一收付款页面选择客户、资金账户、收/付方向、金额和资金日期。可选该客户的任意未归档订单作备注，空订单也可以。订单备注不产生账单、核销或订单结清。
- 草稿提交后进入待财务确认。退回仍使用原单号；审核人不能确认本人提交的待审单。款项确认后形成独立资金事实。
- 财务核销是将已确认的资金金额分配给订单应收或应退。可部分、多单办理，剩余资金继续保留。
- 撤销核销保留原记录、释放可分配资金并恢复订单余额；不改写实际收付款，不等于退款。实际退款须单独登记客户付款并由财务确认。
- 已确认资金不随订单货重、报价、归档或备注变化。订单应收页实时预览报价变化；财务确认时才生成不可变更的调增账单或调减贷项。新报价不回写旧凭证。

## 接口

均位于 `/api/finance/v2`，仅 `finance` / `admin`。业务员可用的资金登记接口见 v1.22。

### GET /order-settlements

参数：`partner_id`（客户，可选）、`q`、`p`、`s`（最多200）。返回 `items,total,page,page_size`。

每行包含：

| 字段 | 意义 |
|---|---|
| order_uid / order_number / customer_id / customer_name | 订单及客户 |
| receivable_amount | 当前有效报价按当前货重计算的应收 |
| legacy_settled_amount | 历史净余额切换中已结算的部分，不重复录入现金 |
| allocated_amount | 当前订单的有效收款核销减付款核销 |
| receivable_balance / refundable_amount | 当前待补收 / 待退（非负） |
| sync_delta | 当前应收与已入账订单账单净额的差额 |
| source_hash | 报价、货物、历史来源、账单及核销版本快照哈希 |
| can_allocate / blockers | 是否可办理及具体待核对原因 |
| documents / source | 关联财务账单与实际来源快照 |

此读取接口不生成账单、不核销、不改变收付款。无有效报价的空订单可作为业务备注，但不能核销不存在的应收。

### POST /order-settlements/{order_uid}/sync

请求：`source_hash, document_date, reason, idempotency_key`。说明必填。

按当前报价确认应收：调增生成客户账单；调减按原账单生成贷项，并抵扣本订单尚未结清部分。已经多收部分保留为应退，不自动修改或冲销收款。返回最新订单应收行。

实时报价不能还原历史时点，因此 `document_date` 仅支持今天，且必须处于开放会计期间。历史处理使用已核准的账单和旧账对账流程。

### POST /order-allocations

```json
{
  "payment_id": 1,
  "version": 3,
  "allocation_date": "2026-10-05",
  "reason": "核对客户付款用途及订单应收",
  "idempotency_key": "unique-request-key",
  "allocations": [
    {"order_uid": "order-uid", "amount": "600.00", "source_hash": "preview-hash"}
  ]
}
```

只接受已确认客户收付款。收款分配给应收，付款分配给应退贷项。每单须同客户，金额不得超过订单及资金可用余额。按订单UID排序锁定，重新检查快照，再在同一事务中确认应收、创建核销和审计。任一订单校验失败，整批回滚。`allocation_date` 同样仅支持今天。

返回 `items`（标准核销记录，增加 `order_uid/order_number`）和最新 `source`（原收付款记录）。原资金金额、账户、凭据号不会改变。

撤销沿用 `POST /allocations/{id}/reverse`，要求版本、撤销日期及原因。核销与撤销均留痕。

## 防重复与旧账切换

- `FinancePayment` 是唯一新资金实体，旧 `POST /api/receipts` 返回410。既有旧待审收款仍可审核/驳回，旧PDF及历史可读。
- 旧已审核资金不得重新复制成新到账。先清理旧待审记录，再由财务核准净余额接入。
- 旧报价差价已包含在当前应收中。确认净余额接入时将原差价任务移交统一订单应收并审计，不生成实际收付款。
- 已进入统一订单应收的订单不能再导入期初，也不能从旧对账接口旁路修改基线。
- 有外部已过账账单、旧人工对账证据、客户变化、历史收款变化等冲突时明确阻止自动接管，须先核准凭据归属；不推测原始资金或静默重复记账。涉及旧账已收部分的调减须先核准历史应退凭据。
- 受管订单账单返回 `order_managed / managed_order_uid`。禁止通过普通核销、手工贷项或冲销绕过订单当前余额检查；创建前及过账时均检查，包括接管前保存的草稿。
- 待审收付款、已接入旧账差异和已管理订单未确认的报价变化均纳入月结检查。
