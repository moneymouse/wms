# 迅达 WMS MCP

服务地址：`https://8.166.137.88/mcp`。
使用 OAuth 2.1 浏览器登录，权限和操作人来自当前 WMS 账号。

## 首次接入

先查找当前会话可用的 WMS MCP 工具。服务名称和工具前缀由客户端决定，
按工具的实际名称、说明和 Schema 识别，不写死平台前缀。

已有连接时直接调用标准 `tools/list` 或客户端工具发现能力。
未连接时，按 [接入说明](references/workbuddy-setup.md) 配置 WorkBuddy 或 Codex 原生
MCP OAuth；也可运行包内的 Python 客户端完成同样的 MCP 协议接入。
该脚本不依赖额外 Python 包，适合在只导入 Skill、尚未配置原生 MCP 时使用。
定位本 Skill 的真实安装目录后调用其中的 `scripts/wms_mcp.py`，不要假设用户
具有开发者仓库路径或 CodeBuddy CLI 专用环境变量。

由用户在浏览器填写自己的 WMS 手机号与密码并选择权限。不要在对话中索取
密码，也不要把密码、访问令牌或刷新令牌写入 Skill、MCP 配置或调用参数。
每位用户独立授权，不共享管理员令牌。不跳过证书校验。

## 使用工具

首次连接以及服务 Schema 变化后，发现工具并以实时 Schema 为准。
普通查询读取 [工具说明](references/tools.md) 的查询部分；创建时再读取创建部分。

| 用户任务 | MCP 工具 |
| --- | --- |
| 分页查询、搜索订单 | `list_orders` |
| 查看指定订单详情 | `get_order` |
| 按业务订单号查询订单下包裹和物流 | `get_tracking` |
| 创建订单，可包含初始报价 | `create_order` |
| 创建草稿装箱单表头 | `create_packing_list` |

仅测试连接时执行工具发现和少量只读查询。用户已明确要求创建并提供足够信息时，
直接执行创建；必要业务信息不清楚时先澄清，不能编造客户 ID、订单 UID 或报价。
这五个工具不提供修改、删除、发货、添加箱子或上传照片能力。

`get_tracking` 需要 `tracking:read`，只传真实业务订单号 `order_id`。
工具精确查找未归档订单并返回订单下包裹，内部 UID 由服务端解析，不先通过
`list_orders` 模糊搜索。每个包裹分别提供仓储状态和物流摘要；无转单号时
`tracking=null`，部分物流查询失败时查看该包裹的 `tracking.error`，外层仍可
为 `code=200`，须同时检查 `tracking_complete`。
查询每次向 17TRACK 请求，同次请求内去重和分批，不使用 WMS 物流缓存，
也不修改仓储状态。17TRACK 的上游采集可能滞后；不要把调用时间描述成
承运商刚刚更新的时间。

## 创建与重试

每次逻辑创建生成一个新的 UUID 作为 `idempotency_key`，在执行前将工具名、键
和参数保留在本次任务中。响应丢失或暂时网络失败时最多自动重试一次，使用同一
工具、原键、原参数和原授权客户端；仍无结果则报告状态不确定，保留原请求以便
后续重试。无法找回原客户端、键或参数时，说明无法安全重试，请用户在 WMS 网页
核实结果；不要生成新键再次创建。参数修正后的新请求使用新键。
不要因超时重新登录或切换客户端后创建。

身份、角色、内部状态与审计字段由服务端提供，不塞入业务参数。
`salesman_id` 是可选业务负责人，不是操作人身份。

## 解读结果

以 `structuredContent` 的业务结果为依据：`code=200` 表示成功，业务失败通常
伴随 `isError=true`。只向用户报告实际返回的 UID 和业务字段，不把 HTTP 200
直接当成业务成功。订单不存在或已归档时说明“订单不存在”。

HTTP 401 时优先由当前客户端刷新；需重新授权时，先处理上面的状态不确定请求，
避免更换客户端破坏幂等范围。403 缺少 scope 时只申请本任务需要的权限。
角色权限不足时说明当前账号无权执行，扩大 OAuth scope 无法改变 WMS 角色。
授予读取权限后仍能发现五个工具，但创建调用需要相应创建 scope。
已有授权不会因服务更新自动增加 `tracking:read`；需要此能力时重新授权，
普通令牌刷新不能扩大原授权范围。
已有此权限的用户不必因参数调整追加授权，重新发现工具获取当前 Schema 即可。
